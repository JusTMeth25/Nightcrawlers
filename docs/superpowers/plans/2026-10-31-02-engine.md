# Nightcrawlers — Piano 02: Engine di gioco (agente Engine)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run survivors-like infinita in Phaser 4 dentro `GameCanvas`, guidata dai dati di `FE/src/data/` e collegata alla UI solo tramite `gameBus`.

**Architecture:** `game/systems/` contiene logica pura deterministica (seed) testata con Vitest, senza import di Phaser. `game/scenes/` e `game/entities/` usano Phaser e chiamano i systems. `game/input/` normalizza tastiera+mouse, touch e gamepad in un `InputState`. `GameCanvas` monta e smonta il gioco e traduce gli eventi.

**Tech Stack:** Phaser 4.2, TypeScript, Vitest (ambiente `node` per `systems/`).

**Spec:** `docs/superpowers/specs/2026-10-31-nightcrawlers-design.md` (sezioni 2, 3.3–3.6)

## Global Constraints

- Lavori solo in `FE/src/game/**`. `shared/`, `data/`, config e asset sono del coordinatore: per modifiche manda una richiesta.
- Nessun commit o file riporta strumenti AI come autori o co-autori.
- Unico export verso React: `export default function GameCanvas(props: GameCanvasProps)`. Nessun import da `FE/src/ui/` o `FE/src/api/`.
- Eventi solo quelli di `GameEvents` (piano 00, Task 3). `hud:update` al massimo 10 volte al secondo. `run:checkpoint` ogni `balance.antiCheat.checkpointEverySec` secondi di gioco (pausa esclusa).
- Il tempo di gioco si ferma in pausa, level-up e apertura baule.
- Tutta la casualità di gioco passa da `createRng(seed)`; nessun `Math.random()` in `systems/` o nelle scene.
- Prestazioni: 60 fps desktop, ≥ 45 fps smartphone medio con 400 nemici; nessuna allocazione per frame nel loop (pool).
- Atlas: `/assets/atlas/heroes.{png,json}`, `/assets/atlas/enemies.{png,json}`; frame `<spriteKey>_<down|side|up>_<action>_<n>`, VFX `<spriteKey>_fx_<n>`. La sinistra è `side` con `flipX`.
- Ogni frame dell'atlas ha un `pivot` sui piedi (frame larghi con il lampo dello sparo restano ancorati). Convenzione: la posizione `x,y` di un'entità sono i suoi piedi; non chiamare `setOrigin` sugli sprite animati (Phaser applica il pivot del frame a ogni cambio frame); collisioni e body Arcade usano le coordinate dell'entità (cerchio centrato sui piedi con offset fisso), non i bordi del frame.

## Review Focus

1. Tab del browser in background e ritorno: il delta di frame enorme non deve teletrasportare entità né far scattare 10 spawn insieme; clamp `delta ≤ 100 ms`. Test in Task 6 (`spawnDue` con delta grande).
2. Gamepad collegato o scollegato durante la run: nessun errore, l'input passa al dispositivo attivo. Test in Task 8 (`mergeInput`).
3. `GameCanvas` montato e smontato due volte di seguito (StrictMode): una sola istanza Phaser attiva, listener `gameBus` rimossi. Test in Task 15.
4. Level-up multipli in un solo frame (molti frammenti raccolti insieme): le offerte arrivano una alla volta, in coda, senza perdere livelli. Test in Task 3 (`pendingLevelUps`).
5. Personaggio con `spriteKey: null` (kiwi, pilar, dorio, falco usati nell'harness): placeholder neon, nessun errore. Test in Task 9.
