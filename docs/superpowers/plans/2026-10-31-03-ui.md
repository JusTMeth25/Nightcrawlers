# Nightcrawlers — Piano 03: UI, meta-progressione e client API (agente UI)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interfaccia React completa (menu, account, selezione personaggio, HUD, level-up, Ripperdoc, Codex, opzioni, privacy) e client API sicuro, con modalità ospite e mock dell'API per sviluppare senza backend.

**Architecture:** react-router per le schermate, zustand per sessione, salvataggio e opzioni. `api/` contiene un client HTTP con access token in memoria, refresh single-flight e header CSRF; un adapter mock implementa la stessa interfaccia. La partita usa `GameCanvas` (piano 02) e comunica solo via `gameBus`.

**Tech Stack:** React 19, TypeScript, react-router 7, zustand 5, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-31-nightcrawlers-design.md` (sezioni 1.1, 2.10, 2.11, 3.2–3.4, 4.4)

## Global Constraints

- Lavori solo in `FE/src/ui/**`, `FE/src/api/**`, `FE/src/App.tsx`, `FE/src/main.tsx`, `FE/src/index.css`. Per `shared/`, `data/`, config o asset manda una richiesta al coordinatore.
- Nessun commit o file riporta strumenti AI come autori o co-autori.
- L'unico import da `game/` è `import GameCanvas from '@game/GameCanvas'`.
- Access token **mai** in `localStorage`/`sessionStorage`: solo in memoria. Lo store persistito (`localStorage`) contiene solo `GameOptions`.
- Nessun `dangerouslySetInnerHTML`; nessuno script o stile inline che violi una CSP `default-src 'self'` (niente `style=` con stringhe generate da input utente; stili statici in CSS Modules o `index.css`).
- Testi in italiano, centralizzati in `ui/i18n/it.ts` (oggetto chiave → stringa).
- Disclaimer fan game (spec 1.1) nella schermata titolo e nel footer.
- Ospite: nessuna chiamata API.
- Ogni schermata è navigabile con tastiera e gamepad (focus visibile).

## Review Focus

1. Access token scaduto durante una richiesta, con più richieste in parallelo: un solo `/auth/refresh`, le richieste vengono ripetute una volta; se il refresh fallisce, sessione chiusa e ritorno al login senza loop. Test in Task 1.
2. Fine run online con rete assente: il `RunResult` non va perso; la UI mostra l'errore e offre "Riprova invio" (il risultato resta in memoria finché la pagina è aperta). Test in Task 6.
3. Utente non verificato che prova a giocare online: messaggio chiaro e possibilità di giocare come ospite. Test in Task 6.
4. Ricarica della pagina da loggato: la sessione si ripristina con `/auth/refresh` all'avvio (il cookie sopravvive, il token in memoria no). Test in Task 1.
5. Modale di level-up con gamepad: stick/D-pad cambia carta, A conferma, nessuna doppia scelta con pressioni ripetute. Test in Task 5.

### Task 1: Client API e sessione

**Files:**

**Interfaces:**
- Consumes: `api-contract.ts` (piano 00, Task 4).
- Produces:
  - `interface ApiClient { register(r: RegisterRequest): Promise<MessageResponse>; verifyEmail(r: VerifyEmailRequest): Promise<void>; resendVerification(): Promise<void>; login(r: LoginRequest): Promise<AuthResponse>; refresh(): Promise<AuthResponse>; logout(): Promise<void>; logoutAll(): Promise<void>; forgotPassword(r: ForgotPasswordRequest): Promise<MessageResponse>; resetPassword(r: ResetPasswordRequest): Promise<void>; me(): Promise<UserDto>; exportData(): Promise<Blob>; deleteAccount(r: DeleteAccountRequest): Promise<void>; getSave(): Promise<SaveDto>; startRun(r: StartRunRequest): Promise<StartRunResponse>; checkpoint(runId: string, c: CheckpointRequest): Promise<void>; endRun(runId: string, r: EndRunRequest): Promise<EndRunResponse>; bestRuns(): Promise<BestRunDto[]>; buyRipperdoc(id: RipperdocUpgradeId): Promise<SaveDto> }`.
  - `class ApiError extends Error { status: number; problem: ProblemDetail | null; retryAfterSec: number | null }`; errori di rete → `ApiError` con `status 0`.
  - `http.ts`: `createHttp(opts: { getToken(): string | null; refresh(): Promise<string | null>; onAuthLost(): void; fetchImpl?: typeof fetch })` con `credentials: 'same-origin'`, header `Authorization: Bearer`, header `X-CSRF-Token` letto dal cookie `XSRF-TOKEN` sulle chiamate `refresh` e `logout`. Su 401 di una chiamata autenticata: un solo refresh condiviso (promise single-flight), ripete la richiesta una volta; refresh fallito → `onAuthLost()`.
  - `api/index.ts`: `export const api: ApiClient` = mock se `import.meta.env.VITE_API_MOCK === 'true'`, altrimenti reale.
  - `MockApi`: stato in memoria che rispetta i codici del contratto (es. 409 €$ insufficienti, 403 non verificato), con utente demo `demo` / `demo-password-123` già verificato.
  - `useSession` (zustand): `{ status: 'unknown' | 'guest' | 'authenticated'; user: UserDto | null; accessToken: string | null; save: SaveDto | null; bootstrap(): Promise<void>; login(r): Promise<void>; logout(): Promise<void>; setSave(s: SaveDto): void; playAsGuest(): void; reloadSave(): Promise<void> }`. `bootstrap` prova `refresh` (successo → `me` + `getSave`; 401 → `guest`).

**Interfaces:**
- Consumes: `api`, `useSession`, `useOptions` (Task 7), `GameCanvas`, `gameBus`.
- Produces:
  - `useRun` (zustand): `{ characterId: CharacterId | null; config: RunConfig | null; result: RunResult | null; outcome: EndRunResponse | null; submitError: string | null; select(id): void; start(): Promise<'started' | 'needs_verification' | 'error'>; onCheckpoint(c: RunCheckpoint): void; finish(r: RunResult): Promise<void>; retrySubmit(): Promise<void>; reset(): void }`.
